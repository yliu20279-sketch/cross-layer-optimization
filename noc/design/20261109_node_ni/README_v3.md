## 保留的数据物理拓扑

16 个 Node 使用基础 Mesh。每个下层 CS 接四个角的 Node；四个指定下层 CS 再分别接对应上层 CS。下层/上层 CS 的既有五向/三向数据交换结构和一次一对输入输出的约束不变。

角 Node 邻接一个下层 CS，边 Node 两个，内部 Node 四个，共 36 条 Node–下层 CS 物理连接，每条有独立发送、接收方向。CS 的 NW、NE、SW、SE 是相对 Node 的位置；Node 西北侧的 CS 使用该 CS 的 SE 方向与此 Node 相连，其余互为相反方向。

## 明确新增的本地配置接口

本轮选定下述接口方案，不再把“无新增数据网络”误写成“零控制导线”。这是一项具体工程设计，不是老师逐位指定的实现。

1. 每个下层 CS 固定由其西北角 Node 的 NI 负责配置。CS(行 r,列 c) 的 owner Node 是 (r,c)。4×4 Node、3×3 下层 CS 的行优先编号下，九个 owner Node 为 0、1、2、4、5、6、8、9、10。每个下层 CS 只有一个配置写入来源，不需要四个相邻 NI 竞争写寄存器。
2. CPU/主机通过现有普通 Mesh 将配置包送到 owner Node 的 NI。NI 检查包类型、完整性与目的地，将配置命令放入独立的有限控制队列。图中蓝色命令输出不接回数据发送队列。
3. owner NI 通过固定的本地命令/响应接口把命令送到对应 CS 侧配置器。配置器读取目标编号、操作与配置内容；目标为本地 CS 时，驱动配置寄存器写入，然后返回响应。CS 数据通路 MUX 不负责自动理解配置包。
4. 上层 CS9/10/11/12 分别通过下层 CS0/2/6/8 的固定配置转接到达。转接接口只传控制命令/响应，不依赖 CS 的数据选择状态。上层仍有自己的命令解析和配置寄存器。没有 Node 到上层 CS 的数据直连。
5. 配置器、转接及寄存器以同一控制时钟域建模。接口跨时钟域时必须另加同步或异步 FIFO，不能直接把本图当作 CDC 设计。

因此要计入九组 NI–下层 CS 本地控制接口和四组下层–上层控制接口，以及配置器、响应寄存器/队列的成本。控制导线可沿已有物理连接布置，但仍是需要面积和时序预算的实际导线，不等于利用数据线就无需控制硬件。命令方向与响应方向均采用有界握手，不画成一个无条件组合写脉冲。

### 命令与响应内容

普通 Mesh 包头负责到 owner NI 的目的地址和包类型；本地配置命令包含 transaction identifier（事务标识）、target identifier（目标 CS）、operation（操作）与 state（寄存器状态）。NI 本地 pause/status/resume 命令由 NI 接收，不转给 CS。图中灰色 NI control 分支表示该路径。

NI 本地控制响应和 CS 返回的写入响应均进入控制队列，经图中 Mesh replies 分支交回发送端，只选择普通 Router 路径回到请求方，不进入 CS 数据通路。待完成请求用事务标识匹配响应；旧响应或目标不匹配的响应不得触发新配置恢复。

本地下层 state 包含三位 output direction、两位 input selection、一位 enable；上层 state 为两位 output direction、一位 input selection、一位 enable。输入编码沿用每个输出 MUX 排除自身后列出的输入顺序。未使用的输出方向编码不产生使能。响应包含原事务标识、目标编号、完成/失败状态；CS 写入响应在目标寄存器的写入边沿之后产生。上层写入必须等待上层确认后才向 NI 返回，不能在下层刚收到时假称完成。

这里只定义字段含义，不擅自规定包头/字段宽度，也不把控制命令填满一个很宽的数据包再宣称无开销。

### 安全切换顺序

配置包始终走普通 Mesh，不依赖可能尚未配置的 CS 数据网络。控制队列、配置响应和 NI 状态处理不占用接收重组的数据缓冲。

固定采用暂停并排空后更新的顺序：

1. 主机通过普通 Mesh 让全部 NI 停止接纳新的 CS 传输；已经接纳的传输允许完成分包、发送、接收和 SRAM 写入，不在一个传输中途冻结剩余片段。
2. 收集全部 NI 的 drain 响应，确认既有 CS 发送队列、接收队列、重组片段和 SRAM 写回均已完成，且不存在在途的已接纳 CS 传输。主机根据实际传输计数/完成记录收集状态，不使用“免费”的全局 empty 信号。
3. 在禁止新 CS 传输期间写入下层和上层 CS 寄存器。一次写入原子更新该 CS 的状态；此期间即使各 CS 在不同时刻更新，也没有数据经过未完成的一半新通路。
4. 收齐所有目标的写入响应，再恢复所有 NI 的新传输。目标错误、超时或部分写失败时保持暂停并报告错误，不带着半套新配置恢复。

这取代需要另画 pending/shadow register 加 commit 树的方案。切换停顿、排空时间、Mesh 配置包和响应均计入开销。普通 Mesh 本身不因 CS 暂停而被关闭。

## 固定的多路径接收方式

### 分流粒度与标识

一条传输按固定最大 payload 大小 F 分成包，最后一个包可以较短。不同包可以选择不同已配置路径，但一个包内部的所有 flit 沿同一路径前进，不使用 flit 级多路径拆分。路径分配服从 CS 一次一对连接、物理链路互斥与无环连续通路约束。

传输描述符由 NPU/主机提供源/目的 NI、源/目的 SRAM 地址、总字节数、允许路径和完成标识。接收描述符必须在发送之前安装并确认有空闲接收上下文。传输标识由源 NI 和其传输序号共同区分，在接收完成和必要确认之前不复用。

每个数据包携带传输标识、byte offset（从此传输起点算起的字节偏移）以及一致的总长度信息。offset 是 F 的整数倍，最后一片长度为总长度减 offset；合法载荷范围和字节有效掩码必须检查。图中 ID 是 identifier，不是新造的模块名。

### 有限缓冲与写回

每条物理接收链路有独立的有限数据队列，Mesh 及 k 个相邻 CS 为 1+k 组；控制包使用独立有限队列。接收仲裁对可服务数据队列轮询。所有 stream 使用 data/valid 正向和 ready 反向；只有 valid 与 ready 同时成立才移动一次数据。基础 Mesh 的既有 credit 协议如与此接口不同，要在 NI 的 Mesh adapter 内转换，不将两种协议直接短接。

重组模块含有界片段暂存、接收上下文、已提交片段 bitmap（收齐位图）和已接纳未写回标记。按传输标识查找接收描述符，验证 offset、长度、边界和重复片段。未知描述符、过界和重复片段产生错误，不把重复包当作新完成量。

每个片段以“目的 SRAM 基地址 + offset”写入它最终的位置，可先写偏移较大的片段，不必须在有限缓冲中等到前一个片段到达。这是内存目的端的按偏移重组，不是所有数据全收齐后再复制一次，也不是宣称网络已按序传输。只有实际 SRAM 写入被接受，才更新此片段的已提交位。所有位都置位、写回全部完成，才产生传输完成通知，NPU 此时才能消费该结果。

这个选择避免“后到片段占满全部重排槽位，最早片段反而无法进入”的典型阻塞。它以可独立寻址的 SRAM 目的区域和事先建立的描述符为前提；若应用要逐 flit 向计算核输出有序流，需要另设有序释放机制，不能直接套用本图。

缓冲深度 Q、暂存槽数 K、活动上下文数 M、每个上下文最大分片数 Nmax 都是有限实现参数，需计入成本和测试。队列/上下文满则反压，不丢数据、不临时无限扩容。SRAM 控制器对 NPU 与 NI 各 bank 请求公平仲裁，新增 CS 通路不带来免费的 SRAM 写入端口。目的区间应保持独占直到该传输完成，不能与另一个未完成传输或 NPU 的原地计算写入重叠。

## CS 握手与原门电路图的关系

原 CS 图展示配置寄存器、数据选择 MUX 和输出使能；本图将一个 stream 当作接口，而不是一根金属线。CS 输出 valid 只在选中输入有效且该连接使能时有效；选中输出的 ready 沿被选择通路反向返回所选输入，未选中输入不得收到伪 ready。该反向选择逻辑还应在 CS 的详细接口/RTL 中落实，不能由“画了双向箭头”代替电路。

Node 图不展开所有 valid/ready 比较器、FIFO 读写使能或配置字段比较器。字段、握手与时序规则由本说明提供。需要流水寄存器的长路径要在实际综合/布线约束下确定；本轮不宣称任意长度路径均一拍。
