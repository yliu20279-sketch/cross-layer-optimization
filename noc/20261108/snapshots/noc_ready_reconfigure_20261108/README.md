## 发现并修正的诊断探针

原 `probe_duplicate_arm` 假定 RUN 响应时已经有非零数据注入。真实接收就绪协议需要 SRAM grant 匹配/删除，允许此时尚为 0。它导致组合回归提前退出，不代表 ARM 真的清空了数据计数。

在独立 NoC 构建中，只调整测试探针：等计数非零后再发送重复 ARM；响应计数不得小于该快照（查询返程允许新流量），epoch/冻结状态必须不变。生产协议、路由、缓冲、带宽和活动应用源码没有改变。
