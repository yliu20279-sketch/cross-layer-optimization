# 移植与验收范围

当前入口对应 Qwen1.5-MoE-A2.7B 的建模路由、512-token prefill + 1 decode、4 请求热诊断。早期 dense Qwen3 和 π0.5 不作为当前工作负载，也没有复制其完整实验目录。

## 保留的数值与算法

- 算子图、原生 OPP 时延/活动、布局、访存校准表、48 个副本候选及其成本规则均来自原冻结输入。
- 核心控制器、RC 脉冲上界、候选选择、资源日历、专家工作区生命周期和付费复制算法不变。
- `runtime/backend.py` 保留原文件。固定 Mesh 的 `Network` 和 `render_trace` 从原模块逐函数提取，函数体未改。未带入其他人的可重构 NoC 实现。
- 输入暖态和 RC 模态数组由原 NPZ 无损转成 float64 JSON；`Infinity` 只用于最后一个热窗口端点，并在加载时还原为正无穷。没有缩放功率、温度、任务量或校准时延。
- Native SRAM 保留策略源码 `build_native_profiles.py` 未改，其 SHA 仍与原 Profile 的实现锁一致。

## 路径和接口调整

- `src/portable.py` 集中解析 `inputs/`、`runtime/` 和输出目录，数值缓存进入忽略的 `.cache/`。
- 原温度试跑入口由小型输入适配器替代；共同暖态由提供的完整 1292 状态读取，原 `validate` 函数保留。
- 冻结布局/OPP 方案放在 `inputs/`，新运行先核对包输入清单，再复制到自己的输出目录。历史机器的源码路径只保留为来源字段。
- 连续运行入口可以在全新检出中建立协议，不依赖先运行探索阶段。首批既有完整任务和通信记录以 SHA256 指纹校验，无需把完整 Trace 放进 Git。
- 审计入口改为读取新运行输出、包内输入和共同暖态。数值、DAG、链路、能量和状态连续性检查保留。
- Native Profile 重放工具只替换初始输入定位，仍调用原执行/缓存类和 `profile_operating_point` 函数；底层 native 计划与 DRAM Profile 已提供，外部工具链重建不在本包承诺范围。
- 独立 RC 核生成工具来自 `analyze_whole_task_opp.operators` 和 `thermal_work_contracts.compile_kernel` 的模型无关部分，输出不覆盖冻结系数。

## 结果与限制

`reference_results/` 是原正式结果的紧凑归档；历史源码哈希和原机器路径不重写成移植版的哈希，避免冒充同一次实验。新的移植验证会另存 `PORTABILITY_VALIDATION.json`。

原正式连续比较为 24 批、96 请求、1,459,776 任务。移植验收只重复选定首批并核对完整任务/通信指纹，不声称再次运行全部 24 批，也不升级为整篇论文的完整系统验收。

原始探索和失败的关键记录：早期 top4 索引源定位修正前的试跑、NumPy 日志序列化问题、严格逐批周期判据探索，以及未处理接近分数时改变调度顺序的模态加速试跑，均未进入正式结果。最终版本对接近的评分和守卫判断使用原物理 RC 算法，并完成正式审计。大体积中断输出仍保留在原工作区，不在本包中复制。

副本/迁移没有被筛掉：完整预复制使系统变慢，成本感知策略没有触发迁移，强制单专家动作只有微小增量。当前契约准入在同选频持续比较中慢 2.394%。这些边界随代码一起保留。

65°C 是人为声明的诊断策略上限；所有对照共用相同输入、初态、资源、OPP 表及边界。Profile 为有界逐任务模型，温度检查针对 1 ms 端点及模型尾部；它不是连续时刻的硅片保证、真实 Gate 轨迹、完整 DRAM 命令队列或作者官方 AMBER 复现。
