# 场景一主性能对照｜固定 Mesh B 与 B＋完整方案

113 执行目录为 `/mnt/sda1/h3240101068/swe_cc_main_perf_evJY8b`。沿用 14 个现有输入、16 节点 Mesh、每应用 6 核和第 0 层 MoE。每组重放固定 Mesh B、B＋完整场景一方案、原 Algorithm 1 消融，共 42 条验证臂。完整方案和原算法复跑使用此前由相应算法选出的配置及逐包分配，审计确认其逐消息完成值与前轮一致。B 始终用原 XY，RTL 检查 CS 配置、占用和载荷为零。

每组的 MoE 刺激文件、CC 请求释放周期、端点、Bank 服务、缓冲和仲裁相同。CC 响应由请求 Bank 完成触发，MoE decode 按各自依赖释放。三组忙态输入中的旧包均在周期 16400 释放，B 走 XY，完整方案起始时用旧 CS 路径传这笔包。两臂保持相同的旧包 ID、包长和依赖定义。忙态开发组的完整方案后来更新配置，两个忙态留出组保留旧配置。

通算后继以首笔请求释放至最后所需响应完成为边界；decode 按该应用首笔 decode 释放至最后 decode 完成计；整段通信取共同起点至最后 Bank 完成。表中绝对时间单位为 RTL 周期，比例按各自固定 Mesh 的时间计算。通算后继 4 组改善、10 组持平；两侧 MoE 的两项指标均为 5 组改善、9 组持平。混合留出首笔响应仍晚 3 周期，整批后继提前 12 周期。

本轮的完整方案指候选扩展、后继完成时间判据和现有 CS 路径在同一 NI／Bank 模型下的实现。范围为单层 RTL 混跑，CC 为合成 GetS，使用现有参数化控制与安装延迟。主表里的整段指这一层样本所覆盖的通信，模型完整请求、Agent 端到端耗时和热管理收益另行评估。

## 证据与复跑

- `main_paired.csv` 为 14 组每项指标的绝对周期、节省周期和百分比。
- `main_aggregate.csv` 按场景提供等权平均、总周期加权结果及改善／持平／退化计数。
- `original_ablation.csv` 为原算法的独立消融，另列完整方案相对原算法的百分比。
- `transactions.csv`、`messages.csv` 分别记录 315 笔事务和 11,670 条消息，包含消融。
- `independent_audit.json` 记录从逐事务、逐消息独立重算后的验收计数和忙态旧包的对照；`main_runs/` 保存 RTL 日志及输入。
- 在 113 上用既有 Verilator 5.006 编译归档中的 `experiment_tb.sv`，与 `mesh_weighted.sv` 和 `aux_packed.sv` 一起以 `unified_tb` 为顶层、使用 `-GWEIGHTED=1 --binary --timing --Mdir obj`。然后在归档目录运行 `python3 -u run_main.py`。冻结输入和原配置选择保存在 `frozen/`。
